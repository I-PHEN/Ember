# Speech alignment implementation plan

Goal: retain Gemini's voice while replacing estimated phrase positions with validated alignment against the actual generated audio.

Architecture: Gemini (existing Edge fallback) → cached audio artifact → local persistent Stable-ts/Faster-Whisper CPU worker → validated word intervals → opt-in narration JSON response → cached browser track → beat phrase timestamps → existing timing compiler. Legacy binary audio callers remain compatible. One bounded alignment runs per synthesized cache entry; failures keep audio and explicit unavailable/invalid/timeout status.

No new hosted API, account or credential. Local setup uses an isolated Python environment and a cached base.en alignment model. Runtime does not download models. English narration is the initial supported alignment language.

## Acceptance

- Speech remains unchanged; alignment uses the exact generated bytes and text, never a regenerated voice.
- No guessed timestamp is labelled aligned. Wrong transcript, missing words, reversed/out-of-bounds timing and low-confidence results are rejected.
- Worker initialization, timeout, malformed output and missing dependencies are contained; audio remains playable.
- Repeated words map monotonically. A phrase cannot end/start partway through a provider word span.
- Legacy get(text) continues to return an audio URL; getTrack(text) additionally exposes timing.
- Runtime worker is a persistent child process, capped CPU threads, bounded request/output sizes and idle shutdown. Model setup is explicit and documented.
- Readiness is checked with real audio where network/model access permits. Fixture tests alone must not be reported as a live alignment verification.
