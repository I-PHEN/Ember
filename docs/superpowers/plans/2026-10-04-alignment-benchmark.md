# Real-audio alignment comparison

Scope: keep Gemini audio unchanged; compare base.en and small.en with the same
CPU int8 configuration, two threads, production 30-second deadline, exact
transcript checks and current rejection rules. No production default changes
until a candidate passes. Phrase-level acceptance is evaluated separately, not
enabled by weakening whole-track validation.

## Reproduction

The three transcripts and board-action anchors are in
`tests/fixtures/alignment-stem.json`. Existing generated Gemini WAVs are local
artifacts in `scratch/alignment/`; they are not committed or regenerated by the
benchmark. Matrix is the original failing sample, unchanged. Equation and
repeated-phrase samples were synthesized once for this comparison.

```powershell
$env:EMBER_ALIGNMENT_MODEL='base.en' # repeat with small.en after model setup
bun tests/alignment-benchmark.live.ts scratch/alignment
workers/alignment/.venv/Scripts/python.exe workers/alignment/inspect_alignment.py base.en scratch/alignment
```

The first command uses the real Node adapter and production validation. It
continues after rejected samples, writes a complete JSON report, and exits 1 if
any sample fails. The second command is an offline diagnostic without the
production timeout: it retains rejected spans and token probabilities to identify
why acceptance failed. Diagnostic output must never be served as validated
timing. Neither command measures human-annotated timestamp accuracy.

## Baseline findings

Clean rerun after initial setup contention:

| Sample | Audio duration | First request | Second request | Accepted track |
| --- | ---: | ---: | ---: | --- |
| Matrix | 11.966 s | 11.476 s (includes process/model startup) | 0.928 s | No |
| Equation | 14.606 s | 1.082 s | 1.162 s | No |
| Repeated phrases | 14.286 s | 1.653 s | 1.124 s | No |

The model worker is reused across samples, so only the first matrix request is
cold. Initial matrix attempts during setup timed out; the clean rerun did not.
Every completed attempt still failed quality validation, so increasing the
deadline alone is not a solution.

Offline inspection:

- Matrix: opening "A" has probability 0.0402; "This", "We" and "choose" have
  zero-length spans. All four board-action phrases avoid those suspect words.
- Equation: "two" in the opening equation has probability 0.0381; "That" and
  "We" have zero-length spans. Four of five action phrases avoid suspect words.
- Repeated phrases: the final "Row" has probability 0.0958. Six of seven action
  phrases avoid suspect words; accepting the first occurrence cannot justify
  accepting the last occurrence.

These are structural/heuristic candidates, not verified accurate phrase times.
Token probabilities are not calibrated alignment confidence. There is evidence
to investigate per-phrase rejection, but no justification for blindly dropping
low-confidence words, inventing their durations, or accepting all phrases.

## Independent-transcription diagnostic

An additional read-only comparison uses native Faster-Whisper recognition with
word timestamps, without forcing the original transcript:

```powershell
workers/alignment/.venv/Scripts/python.exe workers/alignment/inspect_alignment.py base.en scratch/alignment transcribe
```

Matrix and equation recognition had no zero-length or sub-0.15-probability words.
The repeated-phrase sample had one zero-length "Now", outside the action anchors.
However, recognition rendered spoken numbers as digits (including "two x" as
"2x"). This output does not satisfy the current exact-transcript contract and is
not a drop-in production replacement. These results suggest the forced-alignment
method itself merits investigation; they do not establish perceptual timestamp
accuracy. Recognition inference took 7.198 s, 5.748 s and 10.837 s respectively in
this run, with 18.031 s of initial import/model-load overhead.

## Larger-model download outcome

small.en was not benchmarked: its 483545366-byte model could not be downloaded
completely. The normal Hugging Face transfer failed reconstructing the response;
standard HTTP stalled; a bounded direct transfer obtained 26082763 bytes in 120.9
seconds. A subsequent resumable range attempt retained 194765060 bytes across
complete and partial range files before failing. Partial downloads remain under
scratch/alignment/small.en and are not a runnable or hash-verified model.
The public model's published SHA-256 is
`62b2a45b05ee59acb4a5341b33ee35e041395d378d418a18acfe4c9e768ee37a`.
No transfer remains running. No production model or validation rule was changed.
